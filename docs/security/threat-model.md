# Threat model

What Rendered Review protects, where untrusted input crosses into it, what stops each threat, and
what is still open. It covers the web app (`apps/web`) on both runtimes (Node and Cloudflare
Workers) and the packages it uses. Paths are relative to the repository root.

Rendered Review reads pull requests from GitHub, renders their Markdown, and publishes review
comments back to GitHub for the signed-in user. GitHub stays the source of truth: the app stores no
repository content or comments on the server. Only public repositories are served today.

## Assets

| Asset                                                                                                   | Where it lives                                                                                                                   | Why it matters                                                                     |
| ------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------- |
| GitHub user tokens (GitHub App user-to-server access and refresh tokens, OAuth App `public_repo` token) | `account` table, AES-256-GCM encrypted (`packages/identity/src/token-cipher.ts`, `sql-adapter.ts`)                               | Act on GitHub as the user: comment, review, resolve; read what the user can read.  |
| Sessions                                                                                                | Better Auth `session` table; `HttpOnly` cookie in the browser                                                                    | A stolen session acts as the user through the app's endpoints.                     |
| Encryption keys (`ENCRYPTION_KEY`, `ENCRYPTION_KEY_PREVIOUS`), `BETTER_AUTH_SECRET`                     | Platform secret storage                                                                                                          | Decrypt stored tokens; forge session cookies; link trial ledger keys to owners.    |
| GitHub App private key                                                                                  | Platform secret storage; used only in `apps/web/src/github/installation.ts`                                                      | Signs app JWTs; can mint installation tokens for every installation.               |
| Webhook secret                                                                                          | Platform secret storage; `apps/web/src/github/webhook.ts`                                                                        | Forged deliveries would be accepted as GitHub's.                                   |
| Operator public read token (`GITHUB_PUBLIC_READ_TOKEN`)                                                 | Platform secret storage; `apps/web/src/github/proxy.ts`                                                                          | May read private repositories it has access to; its rate limit serves every guest. |
| Private repository content (not served yet)                                                             | Would pass through the user proxy and the browser's memory cache                                                                 | Confidential code and documents.                                                   |
| GitHub App installation records (owners, installations, repository grants)                              | Control-plane tables (`packages/control-plane/migrations`), fed only by signed webhooks (`apps/web/src/github/installations.ts`) | Choose which of the user's tokens a write uses; later, gate private repositories.  |
| Unpublished drafts, preferences                                                                         | Browser IndexedDB (`packages/browser-cache`)                                                                                     | The user's unpublished words.                                                      |

## Trust boundaries

1. **Browser and server:** everything under `/api/` plus the HTML pages and diagram frames.
2. **Server and GitHub:** REST and GraphQL calls with user, operator, app or no credentials.
3. **Webhook ingress:** GitHub calls `/api/github/webhook` server to server.
4. **Untrusted content:** Markdown, MDX and HTML from repositories; comment bodies from any GitHub
   user; the unsigned annotation metadata inside comments.
5. **Diagram frames:** renderer code (Mermaid, Graphviz, Vega and others) runs on author-supplied
   diagram source.
6. **Browser storage:** IndexedDB, the in-memory cache and the service worker cache.

## Threats and mitigations

### 1. Browser and server

| Threat                                             | Mitigation                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  |
| -------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Spoofing / CSRF** on state-changing routes       | The only non-GET routes are the write endpoint, the auth routes and the webhook. `POST /api/github/write/*` requires `X-Requested-With: rendered-review` (forces a CORS preflight that is never answered) **and** `Origin` equal to the app's origin, plus JSON content (`apps/web/src/github/publish.ts`, tests in `publish.test.ts` "request guards"). Auth routes use Better Auth's origin check, forced on even under `NODE_ENV=test` (`packages/identity/src/identity.ts` `advanced`); cross-site sign-in, linking and sign-out are tested (`identity.test.ts`). The webhook is authenticated by its signature instead (section 3). Session cookie is `SameSite=Lax`.  |
| **Session theft**                                  | Cookie is `HttpOnly`, `Secure` (except plain-http localhost), `SameSite=Lax` (`identity.test.ts`). Sign-out deletes the server-side session (tested). No route returns session or provider tokens: everything but sign-in, callback, sign-out, error, linking and `GET /api/auth/viewer` answers 404 (`BROWSER_ROUTES`, tested).                                                                                                                                                                                                                                                                                                                                            |
| **XSS** in the app                                 | CSP with a fresh 128-bit nonce per response; `script-src 'self' 'nonce-…'`, no `unsafe-inline`/`unsafe-eval`; `object-src 'none'`, `base-uri 'none'`, `frame-ancestors 'none'`, `form-action 'self'`, `worker-src 'self'`; `connect-src`/`img-src` limited to the app and the configured GitHub hosts (`apps/web/src/csp.ts`, `csp.test.ts`, checked against the built app on both runtimes by `apps/web/scripts/check-csp.ts`). `style-src-attr 'unsafe-inline'` is allowed for React `style` props only; sanitized Markdown cannot carry `style`. No `dangerouslySetInnerHTML` anywhere; Markdown renders from a sanitized tree to React elements.                        |
| **MIME confusion** on proxied GitHub bodies        | Every response sends `X-Content-Type-Options: nosniff` and the app CSP (`secureResponse` in `apps/web/src/csp.ts`).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                         |
| **Referrer leaks** (which PR a reviewer reads)     | `Referrer-Policy: no-referrer` on every response; `rel="noopener noreferrer"` on every external link (`packages/markdown-domain/src/links.ts`, `apps/web/src/ui/ExternalLink.tsx`).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                         |
| **Open redirect** after sign-in                    | Better Auth checks `callbackURL` against the deployment origin; off-site and protocol-relative URLs are refused (`identity.test.ts` "refuses to redirect off-site"). The browser only navigates to URLs the server returns. The install round trip (`/api/github/install?return=`, `/api/github/setup?state=`) only redirects to a path that resolves to the app's own origin, as an absolute URL (protocol-relative, backslash and tab tricks are tested), and only to an app page that `GET /app` names on the configured GitHub (`apps/web/src/github/install-redirect.ts`, `install-redirect.test.ts`). Its redirects are `no-store`; the setup request writes nothing. |
| **Information disclosure** in errors and logs      | Errors to the browser carry a code and a fixed message or GitHub's own message, never a token. The logger only emits allowlisted, typed fields (`packages/runtime/src/log.ts`); request logs use route templates, never paths (`apps/web/src/request-log.ts`). Tests assert that tokens, bodies and repository names never reach the console (`publish.test.ts`, `user-proxy.test.ts`, `identity.test.ts`).                                                                                                                                                                                                                                                                 |
| **Denial of service** (large bodies, write floods) | Request bodies are read through `readBodyCapped` (`packages/runtime/src/body.ts`): 1 MiB on the write endpoint, 16 KiB on auth routes, 5 MiB on the webhook; reading stops once over the limit. User-proxy responses are capped at 10 MiB. Writes are limited to 60 per user per minute, a review counting one per draft (`publish.ts` `limitRate`).                                                                                                                                                                                                                                                                                                                        |

### 2. Server and GitHub

| Threat                                             | Mitigation                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    |
| -------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **SSRF / open proxy**                              | Proxies only reach `https://api.github.com` or `https://<GHES host>/api/v3` for hosts in `allowedHosts` (github.com plus the operator's `GITHUB_URL`). Paths must match a strict read-only allowlist; the canonical, validated path is what is forwarded (`apps/web/src/github/proxy.ts` `classifyPath`, `proxy.test.ts`).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    |
| **Path traversal** in contents paths               | Each segment is decoded once and refused if it is empty, `.`, `..`, or contains `/`, `\`, `%` or NUL, then re-encoded (`plainFilePath`, tested with encoded traversal). Owner and repository names match `[\w.-]{1,100}` and cannot be `.` or `..`.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                           |
| **Privilege escalation** via credentials           | The broker picks the least-privileged credential (`apps/web/src/github/broker.ts`): viewer reads never use an installation token; writes use the GitHub App user token only where the app is installed, else the OAuth App `public_repo` token. The operator token is used only for its own host and only after the repository is confirmed public; it is never sent elsewhere (`proxy.test.ts`).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                             |
| **Cross-PR writes**                                | Every write rechecks access with the user's token, reads the PR, checks the expected head, and checks that a resolved thread belongs to this PR (`publish.ts`).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                               |
| **Editing someone else's comment** (anchor repair) | `edit` reads the comment through `/repos/{owner}/{repo}/…/comments/{id}` for the type the client names and updates through the same type, so an issue comment ID never reaches a review comment. GitHub scopes comment IDs to the repository in the path (an ID from another repository answers 404, checked against the live API), and the comment must be on this PR number. The author must be the account the token acts for, by GitHub ID (`getAuthenticatedUser`), not login; the OAuth App token is only ever linked to the same GitHub account. The body must equal `repairCommentBody(previousBody)` exactly, `previousBody` must equal GitHub's current body (else 409), a review comment's new selection must overlap its RIGHT-side lines, and a retry that already landed is a no-op (`publish.test.ts` "edit"). The token is the user's own, so GitHub enforces its permissions too. `GET /api/auth/viewer` exposes only the signed-in user's own public GitHub ID, `no-store`. |
| **Installation records choosing the credential**   | The webhook-fed tables only choose between two tokens of the same user (GitHub App user token or OAuth App token) for public repositories; no installation token is ever minted. A stale "installed" makes GitHub refuse the app token's write (the user sees the error); a stale "not installed" falls back to the OAuth App. Where the tables cannot say, GitHub is asked (`localInstallation`, `withLocalInstallations`). The app JWT goes only to the configured GitHub API.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              |
| **Token leakage to GitHub responses / browser**    | Tokens exist only server-side; the browser never sees them (`identity.test.ts` "never hands a GitHub token…"). Server functions expose only which hosts are served, not the read token.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       |

### 3. Webhook ingress

| Threat                                           | Mitigation                                                                                                                                                                                                                                                                                                                                                                                                                                                                                   |
| ------------------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Forged deliveries**                            | HMAC-SHA256 over the raw body with the webhook secret, verified in constant time by Web Crypto, before JSON is parsed or anything is written. Without a secret or database the endpoint 404s (`apps/web/src/github/webhook.ts`, `webhook.test.ts`).                                                                                                                                                                                                                                          |
| **Replay**                                       | Processed delivery IDs are recorded; a repeat is a no-op. The delivery ID header is not covered by the signature, so a captured body could be replayed under a new ID: handlers must be idempotent and must not trust ordering (see residual risks).                                                                                                                                                                                                                                         |
| **Resource exhaustion**                          | 5 MiB cap, content type and header shape checked first.                                                                                                                                                                                                                                                                                                                                                                                                                                      |
| **Out-of-order or replayed installation events** | Rows are keyed by host and GitHub's numeric IDs, never names. A deleted installation stays as a tombstone that no later delivery revives or grants repositories to (GitHub never reuses installation IDs; `0002_installation_deleted_at.sql`). All-repositories installations store no grants, so a large organization costs a few queries. Invalid payloads are dropped and logged by ID only (`installations.ts`, `installations.test.ts`). Other events are last-delivery-wins (R4, R10). |

### 4. Untrusted Markdown, MDX, HTML, comments and annotations

| Threat                                           | Mitigation                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              |
| ------------------------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **XSS through documents or comments**            | `rehype-sanitize` with GitHub's allowlist after `rehype-raw`; `javascript:`, `data:` and other schemes are dropped, scripts, handlers, styles, frames and forms removed, ids prefixed with `user-content-` against DOM clobbering (`packages/markdown-domain/src/render.ts`; XSS fixtures `fixtures/xss.md`, `fixtures/mdx-xss.mdx`; comment rendering in `apps/web/src/review/Markdown.test.tsx`). Source-map markers (`data-rr-*`) are stamped after sanitization, so authors cannot forge them; comments strip them. |
| **MDX code execution**                           | MDX is parsed but never evaluated: JSX, imports and expressions render as inert labelled source (`packages/markdown-domain/src/mdx.ts`).                                                                                                                                                                                                                                                                                                                                                                                |
| **Tracking images / IP leaks**                   | Only repository images and GitHub-hosted images load; every other image becomes a labelled link (`packages/markdown-domain/src/resources.ts`, `docs/privacy-external-resources.md`). `img-src` is built from the same list.                                                                                                                                                                                                                                                                                             |
| **Annotation metadata abused for authorization** | The annotation format is unsigned and is never an authority. On publish it can only cause a refusal: an annotation naming another host, repository or PR is rejected (`checkTarget` in `publish.ts`, tested). Access is decided by the session, the broker and GitHub alone. In the UI an annotation only places and groups comments (`packages/review-domain`). Encoded metadata is capped at 16 KiB (`packages/annotation-domain/src/envelope.ts`).                                                                   |

### 5. Diagram frames

| Threat                                                                   | Mitigation                                                                                                                                                                                                                                                                                                                                                                                                             |
| ------------------------------------------------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Renderer compromise** (malicious diagram source exploiting a renderer) | Renderers run in frames served with `sandbox allow-scripts` (opaque origin, even if opened directly), `default-src 'none'`, a per-response nonce, `frame-ancestors 'self'`, and the iframe also carries `sandbox="allow-scripts"` without `allow-same-origin` (`apps/web/src/diagram/frame.ts`, `frame-client.ts`, `frame.test.ts`). Frames have no network access and no access to the app's cookies, storage or DOM. |
| **Hostile SVG output**                                                   | The page sanitizes renderer SVG with DOMPurify, drops every non-fragment URL and `@import`, and shows it as an `<img>` from a blob URL, where scripts never run and nothing loads (`apps/web/src/diagram/sanitize.ts`, `sanitize.test.ts`).                                                                                                                                                                            |
| **Message spoofing**                                                     | Both sides check `event.source`; the frame's script URL parameter must be a plain same-origin `.js` path.                                                                                                                                                                                                                                                                                                              |

### 6. Browser storage and caches

| Threat                                             | Mitigation                                                                                                                                                                                                                                                                                                                                                                                                                                |
| -------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Private or per-user responses in shared caches** | User-proxy and write responses send `Cache-Control: private, no-store` and `Vary: Cookie`; auth responses `no-store` (`user-proxy.test.ts`, `publish.test.ts`, `identity.test.ts`). The public proxy marks only anonymous or confirmed-public responses `public` (immutable blobs for a year, PR metadata for 30 s, errors `no-store`). The Workers build uses no Cache API; operators must not add "cache everything" rules for `/api/`. |
| **Service worker keeping private data**            | The worker never touches `/api/`, non-GET, cross-origin or `Authorization` requests; it stores hashed assets and only pages that opt in with `X-Rendered-Review-Offline: shell`, and never `private`/`no-store` responses (`apps/web/src/sw/policy.ts`, `policy.test.ts`).                                                                                                                                                                |
| **Private content in IndexedDB**                   | Everything read with the user's access is kept in memory only unless the user opts in (`packages/browser-cache`, `apps/web/src/github/client.ts`). Sign-out reloads the page, dropping it. "Clear local data" empties every store and the service worker caches.                                                                                                                                                                          |

## Token handling

- **At rest:** AES-256-GCM with a random 96-bit IV per value; stored as `<key id>:<base64>` so a row
  names the key that wrote it. Only the token columns of `account` are encrypted, in the database
  adapter, so Better Auth never writes plaintext (`identity.test.ts` "stores GitHub tokens only as
  ciphertext").
- **Rotation:** set the new key as `ENCRYPTION_KEY` and the old one as `ENCRYPTION_KEY_PREVIOUS`.
  Old rows still decrypt; a token is re-encrypted with the new key when it is refreshed. GitHub App
  user tokens refresh every eight hours, so they move over within a day of use. OAuth App tokens do
  not expire and are only rewritten when the user links again. Dropping the previous key makes any
  row it wrote unreadable, which the app treats as signed out (tested). Keep the previous key until
  that is acceptable.
- **In transit:** tokens go only to the GitHub host they belong to, never to the browser, and never
  into logs or error messages.

## Residual risks

Findings from this review that are not fixed in code yet, with severity and what would close them.

| #   | Severity                                 | Risk                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  | What would close it                                                                                                                                                                                                                                                                                                                                                   |
| --- | ---------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| R1  | Medium                                   | **Guest proxy can be used to drain the operator's rate limit.** Anyone can call `/api/github/public/*`; with an operator read token, a flood spends its 5,000 requests per hour for every guest (anonymously, the server's 60 per hour). No per-client limit exists because no runtime-neutral trusted client address is configured.                                                                                                                                                                                                                                                                                                                                                                                                  | A per-client limit keyed on a trusted client IP header (for example `CF-Connecting-IP` on Workers, a configured proxy header on Node), or an edge rate-limiting rule in front of `/api/github/public/`.                                                                                                                                                               |
| R2  | Medium                                   | **Auth route rate limiting depends on the environment.** Better Auth enables its limiter only when `NODE_ENV=production` and keys it on `X-Forwarded-For` by default, which a client can set on Node without a proxy; with no address it falls back to one shared bucket per path. Each sign-in start also writes a short-lived verification row.                                                                                                                                                                                                                                                                                                                                                                                     | Configure Better Auth's `rateLimit` explicitly with a trusted IP header per runtime (same setting as R1), or an edge rule on `/api/auth/`.                                                                                                                                                                                                                            |
| R3  | Low                                      | **Host header chooses the auth origin on Node without `PUBLIC_URL`.** With `PUBLIC_URL` set, the server entry addresses every request to that origin before routing (`atPublicOrigin` in `apps/web/src/auth.ts`, `auth.test.ts`), so Better Auth, redirects and the write endpoint's same-origin check ignore the `Host` header. The Node build refuses to start in hosted or dedicated mode without it. A community Node deployment without it still builds Better Auth per request origin: an attacker can only affect their own requests (GitHub checks the redirect URI, cookies stay host-bound) and the per-origin cache is bounded.                                                                                            | Set `PUBLIC_URL` on every Node deployment.                                                                                                                                                                                                                                                                                                                            |
| R4  | Low                                      | **Webhook replay under a new delivery ID.** GitHub signs only the body. A captured delivery (it travels over TLS, so this needs a compromised intermediary or log) can be replayed with a fresh `X-GitHub-Delivery`. For installations, a replayed `unsuspend` or `added` (or the same events delivered out of order) re-grants until the next event; `deleted` is final. Today that only picks the app token, which GitHub then refuses.                                                                                                                                                                                                                                                                                             | Before private repositories: re-read the installation from GitHub in the handler (`GET /app/installations/{id}` with the app JWT; 404 means deleted) instead of trusting the event's state, and the repository list with an installation token for selected installations. Not done now: it adds GitHub calls to every delivery for no current authorization benefit. |
| R5  | Low                                      | **Visibility cache lag.** The public proxy caches "this repository is public" for five minutes. A repository made private in that window can still be read with the operator token, and immutable blobs are sent `public, max-age=31536000`.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          | Accept (the content was public moments earlier), or shorten the TTL, or drop `public` caching for operator-token reads. Webhooks (`repository.privatized`) could evict the entry.                                                                                                                                                                                     |
| R6  | Low                                      | **App-thread resolution uses `author_association` as write access.** Like GitHub for review conversations, the app honours a resolve or reopen only from the PR author or someone with write access, and offers the Resolve button only to such viewers (the viewer's own repository `permissions`). Other resolution comments stay visible as thread events marked as not changing the state (`threads.ts`, `threads.test.ts`). Per commenter, write access is read from `author_association` (`OWNER`, `MEMBER`, `COLLABORATOR`), which also counts read- and triage-only collaborators and organization members without write access, and can show a member with private organization membership as `CONTRIBUTOR` to some viewers. | Check each resolver's permission with GitHub (`GET /repos/{owner}/{repo}/collaborators/{user}/permission` needs push access; GraphQL `viewerCanResolve` only covers the viewer) if the approximation proves too loose.                                                                                                                                                |
| R7  | Low                                      | **Drafts stay in the browser after sign-out.** Drafts for public PRs persist in IndexedDB so they survive reloads; sign-out does not clear them.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                      | Clear drafts (or everything) on sign-out, or offer it; "Clear local data" already does.                                                                                                                                                                                                                                                                               |
| R8  | Low                                      | **No HSTS header from the app.** Cookies are `Secure` and Cloudflare can enforce HTTPS, but the app does not send `Strict-Transport-Security` itself.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 | Enable HSTS at the edge (Cloudflare) or reverse proxy; the app cannot reliably know the public scheme on Node.                                                                                                                                                                                                                                                        |
| R9  | Low                                      | **Per-instance limits.** The write rate limit, review de-duplication, visibility and installation caches are per process or isolate. Multiple instances multiply the limits.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          | A shared store (KV, database) when running more than one instance.                                                                                                                                                                                                                                                                                                    |
| R10 | Low (Medium before private repositories) | **Installation lookups match by login and name.** `localInstallation` finds the owner by login and the repository by name. A missed account rename whose old login someone else takes, or a missed repository rename, can answer "installed" for the wrong repository until the next event. It only picks between the user's two tokens for public-repository writes (GitHub refuses a wrong app token). Private access never reads these tables: in hosted and dedicated modes the entitlement check (`billing.ts`) asks GitHub live (`GET /repos/{owner}/{repo}/installation` with an app JWT, failing closed), using the owner and name from GitHub's own repository response, and looks the plan up by the owner's GitHub ID.     | Done for private access (`entitlementCheckFor`, tested with a stale "installed" row). Keep the tables out of any future authorization path, or key them by repository ID first.                                                                                                                                                                                       |
| R11 | Low                                      | **Large selected-repository deliveries.** A selected installation writes two queries per repository, one after another. Past the database's per-request query limit (D1: 50 on the free plan, 1,000 paid) the handler fails partway and the delivery stays unrecorded. Anyone can trigger this, for their own installation only; missing grants mean "ask GitHub", so answers stay correct.                                                                                                                                                                                                                                                                                                                                           | Set-based SQL for grants (a fixed number of statements per delivery) or batched statements, portable across SQLite, PostgreSQL and D1.                                                                                                                                                                                                                                |
| R12 | Low                                      | **A repair can overwrite a concurrent edit.** Between reading the comment (checked against `previousBody`) and the update, a collaborator's edit could land and be replaced; GitHub has no conditional update for comments. The window is one GitHub round trip.                                                                                                                                                                                                                                                                                                                                                                                                                                                                      | Accept, or re-read after the update and report when the body is not the repair.                                                                                                                                                                                                                                                                                       |
| R13 | Low                                      | **Install lookup on the failure path.** `/api/github/install` is unauthenticated. The `GET /app` result is cached per config, but while the lookup fails every request signs an app JWT and calls GitHub, spending the app's rate limit, which the installation check shares.                                                                                                                                                                                                                                                                                                                                                                                                                                                         | Cache failures briefly, or an edge rate limit on `/api/github/install` (same setting as R1).                                                                                                                                                                                                                                                                          |
| R14 | Low                                      | **The app's host is inferred from `GITHUB_URL`.** The install redirect sends the app JWT to `GITHUB_URL`'s API and webhook rows are keyed by its host, while the live installation check assumes the app is on github.com. With an Enterprise Server `GITHUB_URL` and a github.com app, the app's JWT (valid ten minutes, can mint installation tokens) goes to that server, over plain HTTP if `GITHUB_URL` is `http:`. The server is operator-configured and trusted, and the lookup then fails.                                                                                                                                                                                                                                    | One setting naming the app's host (default github.com), used by all three, and refusing `http:` wherever credentials are sent.                                                                                                                                                                                                                                        |
| R15 | Low                                      | **Trials follow GitHub owners.** The trial ledger (`apps/web/src/trial.ts`, `docs/privacy-trial-ledger.md`) grants one trial per host, owner type and GitHub owner ID, so every new GitHub organization gets its own, and a personal account converted to an organization (GitHub keeps the ID, the type changes) gets a second. Its HMAC key is derived from `BETTER_AUTH_SECRET`: rotating that secret makes existing entries unmatchable, so every owner could start another trial.                                                                                                                                                                                                                                                | Abuse counters on trial starts per user; a dedicated ledger secret, or keep the old key to re-key the ledger, when `BETTER_AUTH_SECRET` rotation is documented.                                                                                                                                                                                                       |

## Before private repositories launch

These must be true before the app serves or writes private repository content:

1. **Authorization per request:** every private read and write checks, at request time, the user's
   own GitHub access (reading with their token), the GitHub App installation covering the
   repository, the deployment's access policy (`ACCESS_POLICY`) and, when hosted, the owner's
   entitlement. The seams are marked where they refuse private repositories today
   (`user-proxy.ts`, `broker.ts`). An installation token never authorizes a viewer.
2. **No shared caching:** private responses keep `Cache-Control: private, no-store` and
   `Vary: Cookie`; nothing private goes through the public proxy (it refuses non-public
   repositories when it uses a token) or any server or CDN cache. A test proves it for every
   private read path.
3. **Browser storage:** private content stays memory-only unless the user opts in with the policy
   text in `packages/browser-cache`; sign-out and "Clear local data" remove it; the service worker
   never stores it.
4. **Private images:** repository images in private repositories need credentials. Serve them
   through an authenticated, `no-store` path; never via public URLs or tokens in URLs.
5. **Rate limits and abuse:** R1 and R2 closed, so one client cannot exhaust shared limits or the
   auth routes.
6. **Webhook handlers:** installation and repository events that grant or revoke access are
   idempotent and state-based (R4), and revocation takes effect within the cache TTLs (R5, the
   installation check's five minutes) or evicts them. Private access uses GitHub's live
   installation check, never the installation tables, which only choose the credential for public
   writes (R10).
7. **Origin pinning:** `PUBLIC_URL` set on Node deployments (the Node build requires it in hosted and dedicated mode; R3).
8. **Key management:** a documented rotation run (including OAuth App tokens, which never refresh)
   and a way to revoke all sessions.
9. **External review:** an independent review of the private-repository authorization path.
10. **Dependency hygiene:** `pnpm audit --prod` clean of high and critical advisories, or each one
    triaged in writing.
